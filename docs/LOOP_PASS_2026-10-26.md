## What was checked and found fine

- **Electron main (178 rows):** the TensorRT background build (`trtPrebuild.ts`). Its one timer is cleared by start,
  pause and stop. The engine is killed (process group) on pause, stop and quit. Each network's build is bounded
  engine-side (1800 s per network). The minute-by-minute look while blocked runs only in the `blocked` state. The
  first-run and TensorRT install (`install.ts`, 47 rows): local App data, async downloads with connect and stall
  deadlines, async unzip. The cache move: fully async copy, verify and remove. The estimate and ping deadlines. The
  engine's process lifetime: `before-quit` kills the queue's engine, the estimate's and the build's; the engine's
  `end_with_parent` covers a crash on all three systems. The GPU poll: only while a job runs and the window is shown,
  one read at a time, 5 s timeout. State pushes stay ≤ 10/s, with no file-system work in `state()`. The ffmpeg
  install wait is unbounded on purpose (killing apt halfway is worse) and says so.
- **Engine (201 rows):** every per-frame and per-pixel row in `render.rs`, `decode.rs`, `image.rs`, `ocio.rs` and
  `pipeline/keying.rs`. Each runs once per frame, rows in parallel. The allocations are the frame's own outputs; the
  OCIO path uses one buffer per worker. Windows share frames through `Arc`. The windows that need no hint borrow one
  zero buffer. The threads: Ahead / Prefetch producers end when their consumer drops; the writer threads, the
  stdin reader and the parent watch have exit paths. The waits: `proc.rs` deadline polls sleep 50 ms; ck-trt-build has
  1800 s; a failed writer gets 5 s; release gets 300 s. The one retry loop (window halving) is ≤ 7 rounds. `rng.rs`
  rejection loops: each round is accepted with p > 1/2.
- **src (59 rows):** renders over a few sizes, outputs or jobs. The 1 s elapsed tick runs only while the build runs and
  the page is visible. Both copy-feedback timers are cleared.
- **tools and engine-rs/tools (266 rows):** every wait has a timeout or a deadline loop (`mac_gate.sh`,
  `vs_original.sh`, `window_sweep.sh` memory waits, `vs_original_robust.py` engine replies). `gen_notices.mjs:39`
  is flagged no-timeout only because its `timeout: 120_000` is on a wrapped line.
